## Claude Code란

Claude Code는 Anthropic이 만든 **CLI 기반 AI 코딩 에이전트**다. 터미널에서 직접 Claude와 대화하며 코드를 작성하고, 파일을 읽고, 명령을 실행할 수 있다.

단순한 코드 자동완성이 아니라, 레포지토리를 직접 탐색하고 파일을 수정하며 작업을 완료하는 **에이전트 방식**으로 동작한다는 게 핵심이다.

설치는 간단하다.

```bash
npm install -g @anthropic-ai/claude-code
claude
```

> Claude Code를 처음 실행하면 Anthropic API 키 인증이 필요하다. 또는 Claude.ai Pro/Max 구독으로도 사용할 수 있다.
{: .prompt-info }

## 기존 AI 코딩 도구와 비교

현재 시장에는 다양한 AI 코딩 도구가 있다. 각각의 접근 방식이 다르기 때문에, 어떤 도구가 자신의 워크플로우에 맞는지는 직접 써봐야 안다.

| 도구 | 형태 | 동작 방식 | 파일 수정 | 터미널 실행 | IDE 종속 |
|------|------|-----------|:---------:|:-----------:|:--------:|
| **Claude Code** | CLI | 에이전트 (자율 실행) | ✅ | ✅ | ❌ |
| **Cursor** | IDE | 인라인 제안 + 에이전트 | ✅ | ✅ | ✅ |
| **GitHub Copilot** | IDE 플러그인 | 인라인 자동완성 | △ | ❌ | ✅ |
| **Gemini CLI** | CLI | 에이전트 | ✅ | ✅ | ❌ |
| **Aider** | CLI | 에이전트 | ✅ | ✅ | ❌ |

Claude Code와 가장 유사한 포지션은 **Aider**와 **Gemini CLI**다. 모두 터미널에서 동작하는 에이전트 방식이지만, 차이가 있다.

- **Aider** — Git 커밋 중심의 워크플로우. 수정 후 자동으로 커밋을 생성한다. 모델을 자유롭게 선택할 수 있어 Claude, GPT-4, Gemini 등과 함께 쓸 수 있다.
- **Gemini CLI** — Google의 CLI 도구. 무료 티어가 넉넉하고, Google 생태계(Search, Workspace 등)와 연동이 강점이다.
- **Cursor** — IDE 자체를 교체하는 방식이라 에디터 기능과 AI가 가장 자연스럽게 통합된다. 다만 IDE를 바꿔야 한다는 진입 장벽이 있다.

> Claude Code는 **특정 IDE에 종속되지 않는다**는 점과 **Claude 모델의 코드 이해 능력**이 강점이다.
{: .prompt-tip }

## 실제로 어떻게 동작하나

### 버그 수정

가장 유용한 순간은 막연한 요청을 할 때다. 에러 메시지나 증상만 주면 스스로 관련 파일을 찾고, 원인을 분석한 뒤 수정한다.

```
> 로그인 후 리다이렉트가 안 되는 버그가 있어. 확인해줘.
```

이 한 줄로 Claude가 auth 관련 파일을 탐색하고, 로직을 추적하고, 문제를 찾아 수정안을 제시한다. 매번 코드를 복사해서 붙여넣을 필요가 없다.

### 대규모 리팩토링

여러 파일에 걸친 변수명 변경, 패턴 교체, 의존성 정리 같은 작업도 자연어로 요청할 수 있다.

```
> API 응답 타입을 전부 snake_case에서 camelCase로 바꿔줘.
  관련 타입 정의, 파싱 로직, 테스트 파일까지 모두 수정해줘.
```

수십 개 파일을 손으로 고치는 대신, 결과물을 **리뷰하는 데만 집중**할 수 있다.

### Git 작업

커밋 메시지 작성, PR 생성, 브랜치 관리도 Claude Code에서 처리할 수 있다.

```
> 지금 변경사항 커밋해줘. 커밋 메시지도 적절하게 써줘.
> 이 브랜치로 PR 만들어줘. 변경 내용 요약도 포함해서.
```

## CLAUDE.md로 컨텍스트 제공

프로젝트 루트에 `CLAUDE.md`를 두면 Claude Code가 대화 시작 시 이 파일을 읽는다. 프로젝트 구조, 코딩 컨벤션, 주의사항을 여기에 정리해두면 **매번 설명하지 않아도** 된다.

```markdown
# my-project

## 프로젝트 개요
Next.js 14 + TypeScript. App Router 사용.

## 규칙
- 커밋 메시지는 영어, Conventional Commits 형식
- 컴포넌트는 `src/components/` 아래에
- API 라우트는 `src/app/api/` 아래에
- 테스트는 변경한 파일과 같은 디렉토리에 작성

## 주의
- `legacy/` 폴더는 건드리지 말 것
```

> `CLAUDE.md`는 팀 프로젝트에서도 유용하다. 레포에 커밋해두면 팀 전체가 동일한 컨텍스트로 Claude Code를 사용할 수 있다.
{: .prompt-tip }

## Skills로 반복 작업 자동화

`.claude/skills/` 디렉토리에 슬래시 커맨드를 정의할 수 있다. `SKILL.md` 파일에 자연어로 동작을 기술하면, `/skill-name` 형태로 호출할 수 있다.

이 블로그의 `/post` 커맨드가 그 예시다. 날짜 기반 파일명 생성, frontmatter 작성, 카테고리/태그 추론을 자동으로 처리해준다.

```
.claude/
└── skills/
    ├── post/
    │   └── SKILL.md    # /post 커맨드
    └── deploy/
        └── SKILL.md    # /deploy 커맨드
```

## 권한 관리

Claude Code는 파일 수정이나 명령 실행 전에 승인을 요청한다. 민감한 작업일수록 더 신중하게 확인하는 구조다.

> `settings.json`에서 특정 명령이나 경로에 대한 권한을 미리 설정해두면 반복 승인 없이 사용할 수 있다.
{: .prompt-info }

> 프로덕션 DB나 인프라 관련 명령은 항상 수동으로 확인하는 습관을 들이자.
{: .prompt-warning }

## 어떤 개발자에게 맞나

Claude Code는 **터미널 중심으로 작업하는 개발자**에게 특히 잘 맞는다. 에디터를 바꾸지 않아도 되고, 기존 워크플로우에 자연스럽게 추가할 수 있다.

반면 에디터 내에서 AI와 긴밀하게 통합된 경험을 원한다면 **Cursor**가 더 나을 수 있다. 무료로 쓰고 싶다면 **Gemini CLI**가 대안이 된다.

도구는 결국 자신의 작업 방식에 맞는 걸 쓰면 된다. Claude Code는 **"터미널에서 에이전트와 함께 작업하기"를 가장 잘 구현한 도구** 중 하나다.
